Security and privacy

What you enter into the browser tools stays on your device. This page explains how, where the limits are, and what the team workspace prototype does and does not have yet.

The browser tools

  • No server. The app is a static bundle served from this site. All rules run in your browser.
  • No network after loading. The page's content security policy sets connect-src 'none', so the app cannot make a request to any server, including ours.
  • No storage. No cookies, no local storage, no session storage. Closing the tab discards everything.
  • Local downloads. Packets, findings files and draft letters are created in your browser from the values on screen.
  • No third-party code. Scripts and styles are served from this site only; there are no analytics, fonts or embeds from elsewhere.
  • Text rendered as text. Everything you enter is shown as plain text, with bidirectional control characters stripped, so a crafted invoice description cannot inject markup.

Limits

  • The site is hosted on GitHub Pages, which may log requests as any web host does. See the privacy page.
  • Your own browser, extensions and device are outside our control; a compromised device can read anything you type anywhere.
  • The app has not had an independent security assessment. The code is reviewed internally and checked by automated tests, including a check that the shipped bundle contains no inline scripts, styles or data URLs.

The team workspace prototype

The controls below describe code and configuration in the repository. They are not a deployed service, an independent audit or a guarantee; the workspace is not hosted for customers and has processed no customer data.

  • Tenant isolation in the database. Forced row-level security on tenant tables and tenant-scoped transactions, designed to limit cross-tenant reads from any query path. Not independently audited.
  • Roles re-checked on every request from the database, never from a token or header.
  • Four-eyes approval. The author of a claim, of its source data or of a charge label that influenced it cannot approve it; enforced in the application and by database triggers.
  • Tamper-evident audit log and content-hashed evidence packets.
  • Sign-in protection: Argon2id password hashing, multi-factor sign-in for privileged roles, rotating refresh tokens with reuse detection, lockout after repeated failures.
  • API keys stored as keyed hashes, scoped, rate-limited and revocable.
  • Isolated document parsing in separate worker processes with time, memory and size limits and no network access.
  • Abuse limits, server-generated file names and storage keys, and secrets kept out of code and logs.
  • QuickBooks reference data is read-only; access tokens are used per request and never stored.

Not yet

  • Independent third-party security assessment or penetration test.
  • Any compliance certification or attestation.
  • Malware scanning of uploads, production hosting, a tested incident response plan, and a data retention and deletion policy.
  • Product privacy and service terms reviewed for real customer data.
